# Security Design

## Assets to protect
1. Account credentials and private notes stored in the vault
2. Uploaded documents (wills, property papers, ID proofs)
3. Personal letters
4. The release decision itself (it must not be triggered falsely or early)

## Threats and controls

| Threat | Control |
|---|---|
| Database stolen | Secrets, letters and files are encrypted with AES-256-GCM. Tokens are stored as SHA-256 hashes, passwords as bcrypt hashes |
| One vault's key leaks | Each vault uses its own key, derived with HKDF-SHA256 from the master key and the owner id |
| Tampering with stored data | GCM authentication tag: modified ciphertext fails to decrypt |
| Password guessing | bcrypt cost 12, 5-attempt lockout, rate limits on auth and reveal endpoints |
| Account probing | Same error and timing for unknown emails and wrong passwords. Forgot-password always returns "if an account exists…" |
| Session theft through XSS | HttpOnly cookie (unreadable by JavaScript), strict Content-Security-Policy, React output escaping |
| CSRF | SameSite=Lax cookies and a required `X-Requested-With: DLM` header on every state-changing request |
| Accessing someone else's data (IDOR) | Every query is scoped by `ownerId` or nominee membership. Unknown or foreign IDs return 404 |
| Stolen session after a password change | `tokenVersion` in the JWT. Incremented on password change / reset / "sign out everywhere" |
| Malicious uploads | Magic-byte file-type verification, size limit, random file names, served only as attachments with `no-store` |
| Open redirect after login | `next` parameter restricted to internal paths |
| False release (owner alive) | Reminder, then urgent alert, then grace period (≥ 1 day). A nominee report only starts the grace period. Any check-in cancels it |
| Over-sharing after release | Nominees see only the items explicitly assigned to them, and every access is logged in the owner's history |
| Shoulder surfing | Secrets are hidden until the password is re-entered, and hidden again when the dialog closes |
| Demo tools in production | Time travel and mailbox are disabled automatically when `NODE_ENV=production` |

## Key management
- `ENCRYPTION_KEY` (32 random bytes) and `JWT_SECRET` are generated by `npm run setup` and kept only in `server/.env`, which is never committed.
- Losing `ENCRYPTION_KEY` makes stored secrets unrecoverable. Back it up separately from the database.
- Future work: rotate keys by adding a `v2:` ciphertext version (the format already carries a version prefix).
